## TL;DR
- Before Java 5, fixed sets of values (payment status, roles, days) were written as `public static final int`/`String` constants. That gives **no type safety**, **poor readability**, **no grouping** (a `Role` can be compared with a `PaymentStatus`), **duplicate values**, and for Strings, case bugs and slower comparison.
- An `enum` is a **predefined set of constants**. The compiler checks it: a `PaymentStatus` variable can only hold `SUCCESS`, `FAILED` or `PENDING`.
- Under the hood an enum is just a **class**. It's implicitly `final` (in the simple case) and extends `java.lang.Enum`. Each constant is a `public static final` instance created once, and the constructor is always `private`, so no other instances can exist. Comparing with `==` is therefore safe.
- Because it's a class, an enum can have **fields, constructors, getters, methods, and even abstract methods** that each constant overrides (constant-specific bodies). It can implement interfaces but **can't extend** a class.
- Built-ins: `name()` and `ordinal()` come from `Enum`. `values()` and `valueOf(String)` are **generated by the compiler** for each enum.

## Key Concepts

**The constants problem.** `int SUCCESS = 1` is still just an `int`, so any int (e.g. `100`) is accepted, `status == 2` doesn't say what it means, and unrelated constant groups can be mixed. *Why it matters:* these bugs only show up at runtime, when the app is already live.

**Enum (enumerated type).** `enum PaymentStatus { SUCCESS, FAILED, PENDING }` declares a type with exactly those values. *Why it matters:* mistakes become **compile-time** errors.

**Enum = class.** The compiler turns an enum into roughly `final class PaymentStatus extends Enum<PaymentStatus>` with one `public static final` field per constant, each initialized with `new PaymentStatus(...)`. *Why it matters:* everything you know about classes applies.

**Singleton constants.** The constructor is private and the class can't be instantiated from outside, so each constant is the **only** object of its kind. Every variable holding `Direction.NORTH` points to the same object. *Why it matters:* `==` comparison is correct and fast, and the objects work as "markers".

**Fields and constructors.** `NORTH(0), EAST(90)` passes arguments to the enum's constructor, so each constant carries its own data. *Why it matters:* you can attach metadata such as degrees, codes or labels.

**Constant-specific methods.** Declare `abstract void move();` in the enum and give each constant a `{ ... }` body that overrides it. Each body is like an anonymous subclass. *Why it matters:* you get per-value behavior without `switch`/`if` chains.

**Built-in methods.** `values()` (a copy of all constants as an array), `valueOf(String)` (exact, case-sensitive lookup; throws `IllegalArgumentException`), `name()` (final, the exact declared name), `ordinal()` (0-based position) and `toString()` (overridable, defaults to the name).

## Detailed Notes

### The problem: constants before enums [00:30]
- Scenario: payment status can only be **success, failed or pending**, and the whole app needs to share these values.
- Pre-Java-5 approach: a class holding constants:
  `class PaymentStatus { public static final int SUCCESS = 1, FAILED = 2, PENDING = 3; }`
  - `final` because they never change. Upper-case names by convention.
  - `static` so they belong to the class (not to each object) and can be used as `PaymentStatus.SUCCESS` without creating objects.

### Problems with `int` constants [04:07]
1. **No type safety.** `int status = 100;` compiles even though 100 means nothing. You want errors at **compile time**, not runtime, because runtime means the bug is already in production.
2. **Poor readability** [06:30]. In `if (status == 2)`, a reader has to open `PaymentStatus` to learn that 2 means FAILED.
3. **No grouping of related entities** [07:40]. Add `class Role { USER = 1, ADMIN = 2 }`. Now `if (status == Role.ADMIN)` compiles, since it's int against int, and silently means "FAILED".

### Strings don't fix it [07:57]
- `public static final String SUCCESS = "Success"`. Comparing with a hand-typed `"success"` fails because of case, and you end up normalizing case everywhere.
- String comparison works character by character, so it's slower than comparing ints or references.
- **Duplicates are allowed** [10:26]. `MANAGER = 2` next to `ADMIN = 2` compiles without complaint, for both ints and Strings.

### Enter `enum` (Java 5) [11:13]
- Short for **enumeration** (enumerated type): a **predefined set of constants**.
- Syntax: `enum PaymentStatus { SUCCESS, FAILED, PENDING }`. You don't write `public static final`, a type, or a value.
- Usage [13:25]: `PaymentStatus status = PaymentStatus.SUCCESS;`. The variable's type is now the enum.
  - `PaymentStatus s = 100;` is a type-mismatch compile error ("cannot convert from int").
  - Assigning `"error"` is also a compile error.
  - `if (status == "success")` is a compile error (incomparable types).
- `status.name()` prints `SUCCESS`.

### An enum is a class [16:35]
- Example used for the rest of the lecture: `enum Direction { NORTH, SOUTH, EAST, WEST }`.
- After compilation, the enum **is a class** [16:58]. The `enum` keyword just marks it as special.
- It implicitly **extends `java.lang.Enum<Direction>`** [18:21]. `java.lang` is auto-imported, so you don't write any of this.
- Each constant is implicitly `public static final` and has type `Direction`. It's an **object of the enum's own class**.
- Roughly what the compiler generates:
  ```
  final class Direction extends Enum<Direction> {
      public static final Direction NORTH = new Direction();
      public static final Direction SOUTH = new Direction();
      public static final Direction EAST  = new Direction();
      public static final Direction WEST  = new Direction();
      private Direction() {}          // private: nobody else can call new
  }
  ```
  (The real constructor also passes the name and ordinal to `Enum`'s constructor.)
- **Private constructor** [21:35]. `new Direction()` outside the enum is impossible, so exactly four objects ever exist.

> **Correction:** the video says every enum "overrides" the `Enum` class. It **extends** it. Also, the class is `final` only when no constant has a body. With constant-specific bodies (see below) the compiler makes it non-final, so that those bodies can be its anonymous subclasses, but it still can't be subclassed in source code.

### Memory picture [22:54]
- Each `new Direction()` allocates one object on the heap. The static references `NORTH`, `SOUTH`, `EAST` and `WEST` point to them. (The video shows them in "stack/static memory". Static fields actually live with the class data, but the point stands.)
- These objects are **empty**, because the only fields are static. They work purely as **markers**.
- `Direction d1 = Direction.NORTH; Direction d2 = Direction.SOUTH; Direction d3 = Direction.NORTH;` creates three references to existing objects and no new objects.
- So `d1 == d3` is **true** [29:00]: both point to the NORTH object.
- Another classic use: `enum DayOfWeek { MONDAY, …, SUNDAY }` [31:05]. You write one line and Java builds the whole class.

### Enums can have fields, constructors and methods [32:49]
- Since it's a class, an enum can have state and behavior. Example: compass degrees, with NORTH = 0°, EAST = 90°, SOUTH = 180°, WEST = 270° [34:22].
- Code [35:00]:
  ```
  enum Direction {
      NORTH(0), SOUTH(180), EAST(90), WEST(270);   // semicolon needed when members follow
      private final int degree;
      Direction(int degree) { this.degree = degree; }
      public int getDegree() { return degree; }
  }
  ```
  `Direction.SOUTH.getDegree()` gives 180.
- Generated code [38:24]: `NORTH(0)` becomes `new Direction(0)`. Each object now holds its own `degree` field, set through the constructor. Methods aren't stored in objects.
- Whether or not you write a constructor, and whatever modifier you give it, it's **always private**. Only the declared constants may exist.

> **Note:** the hand-drawn memory picture in the video swaps EAST and SOUTH (90 vs 180). The code (SOUTH = 180, EAST = 90) is right.

### Abstract methods and constant-specific bodies [42:37]
- Goal: one method `move()` that behaves differently for each direction. NORTH → y+1, SOUTH → y−1, EAST → x+1, WEST → x−1.
- Without enums you'd write an abstract class `Direction` plus subclasses (`NorthDirection`, …), or anonymous classes [47:30]: `new Direction() { @Override public void move() {...} }`.
- With an enum [44:53]: declare `public abstract void move();`. The compiler then demands that every constant implement it ("The enum constant NORTH must implement the abstract method move()"). Each constant gets a body:
  `NORTH { public void move() { System.out.println("Move up: y + 1"); } }, ...`
- Internally this is `public static final Direction NORTH = new Direction() { ...override... };`, an anonymous subclass per constant.
- `Direction.NORTH.move()` prints the north behavior.

### Built-in methods: where they come from [51:24]
- Four important methods: `values()`, `valueOf(String)`, `name()` and `ordinal()`.
- Interview trap [52:55]: only **`name()` and `ordinal()`** come from `java.lang.Enum`. **`values()` and `valueOf(String)` are generated by the compiler** for each enum. Look in `Enum.java` and you won't find them in that form.

### `values()` [54:01]
- `Direction[] dirs = Direction.values();` gives an array of every constant in declaration order.
- Iterate with the **for-each loop**: `for (Direction d : dirs) System.out.println(d.name());` prints NORTH, SOUTH, EAST, WEST.
- Use case: populating a dropdown or menu from an enum.

### `valueOf(String)` [56:56]
- Converts a String into the matching constant: `Direction.valueOf("EAST")` gives `Direction.EAST`.
- **Case-sensitive and exact.** `valueOf("East")` throws **`IllegalArgumentException`** [58:05].

### `name()` vs `toString()` [58:36]
- `name()` returns the exact declared name. `toString()` returns the same thing by default, and `println(d)` calls `toString()`.
- **Difference** [59:24]: you can **override `toString()`** (e.g. return `name() + " direction"`), but **`name()` is `final`**. Trying to override it gives "Cannot override the final method from Enum".

### `ordinal()` [60:33]
- The 0-based position in the declaration. With `NORTH, SOUTH, EAST, WEST`, `EAST.ordinal()` is `2`.
- It's rarely useful, because it changes if you reorder the constants.
- Enums also inherit `Object` methods (`equals`, `hashCode`, …).

### What enums can't do [62:04]
- An enum **can't extend another class**, because it already extends `Enum` and Java allows only one superclass.
- It **can implement any number of interfaces**.

### How `values()` works internally [64:22]
- The compiler also generates `private static final Direction[] $VALUES = { NORTH, SOUTH, EAST, WEST };` (the video calls it "StarValues"; it's actually `$VALUES`).
- `public static Direction[] values() { return $VALUES.clone(); }`. It's static because you can never get an instance any other way.
- Why the compiler generates it: only the compiler knows how many constants each enum has. The generic `Enum` class can't.
- Why `clone()`: so callers get a **copy** of the array and can't reorder or overwrite the internal one. The copy is shallow, but that's fine here: the elements are references to the same singleton constants, which can't be replaced anyway.

### How `valueOf(String)` works internally [69:00]
- `Enum` does have a `valueOf`, but with a different signature: `static <T> T valueOf(Class<T> enumClass, String name)`.
- The compiler-generated `Direction.valueOf(String s)` simply calls `Enum.valueOf(Direction.class, s)`. `Direction.class` (a `Class` object) comes back with reflection.

### When to use enums [71:12]
- Any **small, fixed set of values**: days of the week, payment status, order status (PENDING, DELIVERED, …), log levels (INFO, DEBUG, ERROR), roles.

## Code Examples

Each block is a complete program. Save it under the class name (e.g. `IntConstantsProblemDemo.java`) and run it with `java IntConstantsProblemDemo.java`.

### The `int` constants problem
```java
public class IntConstantsProblemDemo {
    static class PaymentStatus {
        public static final int SUCCESS = 1;
        public static final int FAILED = 2;
        public static final int PENDING = 3;
    }

    static class Role {
        public static final int USER = 1;
        public static final int ADMIN = 2;
        public static final int MANAGER = 2;   // duplicate value: compiler doesn't care
    }

    public static void main(String[] args) {
        int status = 100;                      // no type safety: compiles fine
        System.out.println(status);            // 100

        status = PaymentStatus.FAILED;
        if (status == Role.ADMIN) {            // no grouping: comparing status with a role
            System.out.println("Looks like ADMIN?!"); // Looks like ADMIN?!
        }
        System.out.println(Role.ADMIN == Role.MANAGER); // true (duplicates)

        String s = "Success";
        System.out.println(s == "success" || s.equals("success")); // false (case bug)
    }
}
```

### Enum basics: type safety, `==`, `switch`, built-in methods
```java
public class EnumBasicsDemo {
    enum PaymentStatus { SUCCESS, FAILED, PENDING }

    enum Direction {
        NORTH, SOUTH, EAST, WEST;

        @Override
        public String toString() {             // overridable (name() is final)
            return name() + " direction";
        }
    }

    public static void main(String[] args) {
        PaymentStatus status = PaymentStatus.SUCCESS;
        // PaymentStatus bad = 100;            // compile error: incompatible types
        System.out.println(status.name());     // SUCCESS

        switch (status) {                      // enums work great with switch
            case SUCCESS -> System.out.println("Paid");   // Paid
            case FAILED -> System.out.println("Retry");
            case PENDING -> System.out.println("Wait");
        }

        Direction d1 = Direction.NORTH;
        Direction d3 = Direction.NORTH;
        System.out.println(d1 == d3);          // true (same singleton object)

        for (Direction d : Direction.values()) {
            System.out.print(d.name() + "=" + d.ordinal() + " ");
        }
        System.out.println();                  // NORTH=0 SOUTH=1 EAST=2 WEST=3

        Direction e = Direction.valueOf("EAST");
        System.out.println(e.name());          // EAST
        System.out.println(e);                 // EAST direction  (toString override)
        System.out.println(e.ordinal());       // 2

        try {
            Direction.valueOf("East");         // case-sensitive
        } catch (IllegalArgumentException ex) {
            System.out.println("IllegalArgumentException"); // IllegalArgumentException
        }
    }
}
```

### Fields, constructor, getter, and an interface
```java
public class EnumFieldsDemo {
    interface Describable { String describe(); }   // enums may implement interfaces

    enum Direction implements Describable {
        NORTH(0), SOUTH(180), EAST(90), WEST(270);  // calls the constructor

        private final int degree;

        Direction(int degree) {                    // implicitly private
            this.degree = degree;
        }

        public int getDegree() { return degree; }

        @Override
        public String describe() { return name() + " at " + degree + " degrees"; }
    }

    public static void main(String[] args) {
        Direction d = Direction.NORTH;
        System.out.println(d.getDegree());              // 0
        System.out.println(Direction.SOUTH.getDegree()); // 180
        System.out.println(Direction.EAST.describe());   // EAST at 90 degrees
        // new Direction(45);   // compile error: enum types may not be instantiated
    }
}
```

### Abstract method with constant-specific bodies
```java
public class EnumAbstractMethodDemo {
    enum Direction {
        NORTH { public void move() { System.out.println("Move up: y + 1"); } },
        SOUTH { public void move() { System.out.println("Move down: y - 1"); } },
        EAST  { public void move() { System.out.println("Move right: x + 1"); } },
        WEST  { public void move() { System.out.println("Move left: x - 1"); } };

        public abstract void move();   // every constant MUST implement this
    }

    public static void main(String[] args) {
        Direction d = Direction.NORTH;
        d.move();                       // Move up: y + 1
        Direction.WEST.move();          // Move left: x - 1

        // Each body is an anonymous subclass of Direction:
        System.out.println(Direction.EAST.getClass() == Direction.class);            // false
        System.out.println(Direction.EAST.getDeclaringClass() == Direction.class);   // true
    }
}
```

### Roughly what the compiler generates (hand-written imitation)
```java
import java.util.Arrays;

public class EnumInternalsDemo {
    // A hand-written imitation of: enum Direction { NORTH, SOUTH, EAST, WEST }
    static final class Direction {
        public static final Direction NORTH = new Direction("NORTH", 0);
        public static final Direction SOUTH = new Direction("SOUTH", 1);
        public static final Direction EAST  = new Direction("EAST", 2);
        public static final Direction WEST  = new Direction("WEST", 3);

        private static final Direction[] $VALUES = { NORTH, SOUTH, EAST, WEST };

        private final String name;
        private final int ordinal;

        private Direction(String name, int ordinal) {   // private: no outside instances
            this.name = name;
            this.ordinal = ordinal;
        }

        public static Direction[] values() { return $VALUES.clone(); } // copy protects $VALUES

        public static Direction valueOf(String s) {
            for (Direction d : $VALUES) if (d.name.equals(s)) return d;
            throw new IllegalArgumentException("No enum constant Direction." + s);
        }

        public final String name() { return name; }
        public final int ordinal() { return ordinal; }
        @Override public String toString() { return name; }
    }

    public static void main(String[] args) {
        Direction[] copy = Direction.values();
        copy[0] = null;                                  // only the copy changes
        System.out.println(Arrays.toString(Direction.values())); // [NORTH, SOUTH, EAST, WEST]
        System.out.println(Direction.valueOf("EAST").ordinal()); // 2
        System.out.println(Direction.valueOf("NORTH") == Direction.NORTH); // true
    }
}
```

## Common Pitfalls / Tips
- **Compare enums with `==`.** It's null-safe on the left and compile-time checked. `equals` works too but adds nothing.
- **`valueOf` is case-sensitive and throws** `IllegalArgumentException` (and `NullPointerException` for `null`). When parsing user input, normalize it (`input.trim().toUpperCase()`) and catch the exception, or loop over `values()`.
- **Don't persist `ordinal()`.** Reordering or inserting a constant silently changes every ordinal. Store `name()`, or an explicit code field.
- **A semicolon is needed after the constants** when the enum has fields, constructors or methods.
- **Constructors are always private.** Writing `public` is a compile error.
- **An enum can't extend a class** (it already extends `Enum`), but it can implement interfaces.
- **`values()` allocates a new array on every call.** In hot loops, cache it in a `private static final` field.
- **Use `EnumSet` and `EnumMap`** for sets and maps keyed by enum constants. They're backed by bit vectors and arrays, so they're very fast.
- **An enum with a single constant is the recommended singleton pattern** (`enum Config { INSTANCE; }`). It's safe against serialization and reflection attacks.
- **Override `toString()` for display text and leave `name()` alone.** `name()` is `final` for a reason: `valueOf` depends on it.

2. Why don't String constants solve those problems?
3. What does the compiler turn `enum Direction { NORTH, SOUTH, EAST, WEST }` into? Mention the superclass, the field modifiers and the constructor.
4. Why is `d1 == d3` true when both were assigned `Direction.NORTH`?
5. How do you give each enum constant a degree value, and why is the constructor private?
6. How can each constant behave differently for the same method?
7. Which of `values()`, `valueOf()`, `name()` and `ordinal()` come from `java.lang.Enum`, and which are compiler-generated? Why?
8. What's the difference between `name()` and `toString()`? Why does `values()` return a clone?

<details>
<summary>Answers</summary>

1. No type safety (any int such as 100 is accepted), poor readability (`status == 2`), no grouping (`status == Role.ADMIN` compiles), and duplicate values are allowed. All of these bugs surface at runtime.
2. Strings are still "any String". You get case-sensitivity bugs (`"Success"` vs `"success"`), slower character-by-character comparison, and still no grouping or duplicate protection.
3. Roughly `final class Direction extends Enum<Direction>` with `public static final Direction NORTH = new Direction(...)` for each constant, a `private` constructor, a `$VALUES` array, and the generated `values()`/`valueOf(String)` methods.
4. Each constant is a single object created once. Assigning `Direction.NORTH` copies the reference to that same object, and `==` compares references.
5. Add a field, a constructor and a getter, and write `NORTH(0), SOUTH(180), ...`. The constructor is private so nobody can create more instances: the declared constants are the only ones.
6. Declare an `abstract` method in the enum and give each constant a body `{ ... }` that overrides it. Each body is effectively an anonymous subclass.
7. `name()` and `ordinal()` come from `Enum`. `values()` and `valueOf(String)` are compiler-generated, because only the compiler knows the specific constants of each enum. (`Enum` has only the two-argument `valueOf(Class, String)`, which the generated one calls.)
8. `name()` is final and always returns the declared identifier. `toString()` returns the same by default but can be overridden for display. `values()` returns a clone so that callers can't modify the internal `$VALUES` array.
</details>
